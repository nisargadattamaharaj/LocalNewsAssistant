## 2. Продукт и границы проекта

LocalNewsAssistant — самостоятельное Android-приложение для преимущественно локального получения, хранения, поиска, экспорта и анализа новостей и обсуждений.

Основная цепочка: коннектор → нормализация → разрешённое локальное хранение → поиск → отбор контекста → локальная LLM → проверка → отчёт со ссылками.

Целевой сценарий «Умный архив» задан ROADMAP, включая дополнения23–24окт и §13:
- выбранные сообщения, история за период и вся доступная разрешённая история источников, включая ветки и ответы;
- общий локальный архив оригиналов и связей, поиск, snapshots и выбранный корпус;
- список сохраняемых правил архивирования/актуализации и поиска/мониторинга;
- первоначальное получение, продолжение прерванного задания, довыгрузка нового и расширение старого диапазона без полной повторной истории;
- исторические совпадения списком; уведомления предназначены новым сообщениям, а не потоку старой истории;
- экспорт JSONL и удобных текстовых профилей TXT/Markdown для внешних LLM отдельно от локального анализа;
- сохранение уже полученной записи после обычного удаления оригинала — требование пользователя, не установленное разрешение хранить любые материалы навсегда.

Rule, отдельный Run, прогресс получения, прогресс проверки и MatchResult — разные сущности. Голый messageId не глобальный ключ. Два крайних ID или lastRunAt не доказывают полноту диапазона. Изменение ключей не должно само по себе требовать повторного скачивания разрешённого архива. Точные схемы, алгоритмы прогресса и политика уведомлений ещё не реализованы и не утверждены автоматически предложениями PLAN.

Архив, поиск и экспорт полезны без установленной модели и без принятого качества LLM. Полный архив, экспорт выбранного диапазона и ограниченный вход одного LLM-запроса различаются. Первая внешняя передача предполагает явное действие пользователя, не обязательный сервер или автоматическую API-отправку.

Начальный runtime — LiteRT-LM, изолированный за интерфейсом. Модель не включать в APK; локальный импорт сохраняется, получение модели развивается отдельно. Секрет Hugging Face не становится обязательным для всех сценариев. Стабилизация JSON/UI не означает принятия смысла сводок.

TDLib подключает пользовательский Telegram-аккаунт. Необязательный бот — интерфейс команд/доставки, не обязательный движок сбора или анализа. Выбранный источник не становится достоверным автоматически. Реальные получение, хранение, индексирование, экспорт и AI-обработка требуют отдельного допуска; локальность и публичность его не заменяют.

Целевая нижняя навигация по ADR-13: Главная · Подключения · Чат · Настройки. Источники управляются в Подключениях. Это целевая структура, не заявление о реализации всех экранов. Сложный DI, сервер, многомодульность, function calling и мультимодальность до устойчивого базового сценария не добавлять. RSS не вводить как обязательный маршрут; Threads/LinkedIn — будущие официальные коннекторы после проверки API/прав, без обходов и неофициального scraping.

Текущая проверенная реализация — технический прототип и принятые подэтапы Room/поиска/UI, ограниченный restart-сценарий и debug native-load104. Полный продуктовый архив, правила, получение сообщений, экспорт, уведомления и качество LLM не объявляются готовыми.
